## P0 — 阻断「把合集装全」

### A12. mod 目录名过长 → `ENAMETOOLONG`，6 个 mod 安装失败

- **现象**：`io_error: cannot move extracted files into place: 文件名过长`
- **复现对象**（6 个，均以超长的站内名命名）：
  `Draugrs - My patches - SE by Xtudo - Diverse Dragon Priests … (一长串) … Xavbio Dragon Priests` 等，mod 名有 **150–250 字符**。
- **根因**：`core/src/mod_install.cpp:130` 的 `sanitize()` 只替换非法字符、**不限制长度**；mod 目录名直接取站内全名，解压后内部路径再拼接 → 超过单段 255 字节 / 路径上限。抛错点在 `core/src/mod_install.cpp:302`。
- **建议修复**：
  - `sanitize()`（或 `sanitize_mod_name`）对**最终目录名**做长度上限（建议 ≤ 100 字节，按 UTF-8 字符边界截断），超出时追加**稳定短哈希**（如 `xxh64` 前 8–10 个 hex）保证唯一。
  - 保证 `meta.ini` / `modlist.txt` / `state.json` 里用的是同一个名字；重跑时必须**同名幂等**（不能每次生成新名字）。
  - 注意 `mod_name_taken()`（`mod_install.cpp:174`）的去重也基于该名字。
- **验收**：重跑 `collection install`，这 6 个 mod 安装成功，且 `failed` 里不再出现 `文件名过长`。

### A13. FOMOD `moduleconfig.xml` 的 encoding 声明错误 → 直接解析失败，1 个 mod 失败

- **现象**：`invalid_argument: invalid XML: encoding specified in XML declaration is incorrect at line 1`
- **复现对象**：`Hidden Hideouts of Skyrim - Merged NavMeshed`
- **根因**：`core/src/xml.cpp:87` 直接抛 expat 的 `XML_ErrorString`。真实 FOMOD 里存在「声明与实际内容编码不符」的文件（MO2 能容忍）。
- **建议修复**：遇到编码类错误（`XML_ERROR_INCORRECT_ENCODING` 等）时**降级重试**：把 XML 声明里的 `encoding="…"` 去掉（或强制 `XML_SetEncoding(p, "UTF-8")`），再按 BOM 判断 UTF-8/UTF-16 重解析。
- **验收**：该 mod 安装成功。

### A14/A15. 清单的 FOMOD `choices` 与归档对不上 → **34 个 `pending [fomod_choices]`**

这是最影响结果的一项：pending 里全是**核心视觉 mod**（SMIM、Skyland AIO、Lux (main)、Embers XD 2K、Majestic Mountains、Beyond Skyrim - Bruma/Assets、Particle Patch for ENB、Glorious Doors、Nordic UI…），**不修就永远装不全**。

两种报错（`collection status` 的 `pending[].detail`）：
1. **choices 对不上归档**（A14）：`core/src/collection.cpp:690` 包住 `core/src/fomod.cpp` 抛的错：
   - `Skyrim Unbound Reborn` → `group 'Timing is Everything' needs exactly one choice`（`fomod.cpp:409`）
   - `(ESL) Immersive World Encounters AddOn - High Poly Uniques` → `no plugin 'Finish Installation' in group ' ' of step 'Installation'`（`fomod.cpp:400`）
2. **清单没给选择**（A15）：`this FOMOD installer needs choices: run fomod inspect …`

**已定位的相关代码**：
- 解析清单选择：`choices_from_vortex`（`core/src/collection.cpp:105-124`）——按 `options[].name / groups[].name / choices[].name` 建 `Choices{step→group→set}`。
- 应用选择：`core/src/fomod.cpp:380-418`——按 `step.name` / `group.name` / `plugin.name` **精确匹配**；找不到就 `bad(...)`。
- 失败归类：`core/src/collection.cpp:690`。

**调查建议**（需要拿真实样例对比，不能盲改）：
- 用现场归档复现单例：`mo-linux -i /mnt/skyrim/Constellations fomod inspect "<downloads 里的对应压缩包>"`，打印归档 FOMOD 的真实 step/group/plugin 名，与 `state.json`/清单里该 mod 的 `choices` 结构逐字段对比。
- 重点怀疑：
  - 清单（Vortex）的 **step/group 名与归档不一致**（如 group 名是空串 `' '`，或带「Installation/Finish Installation」这类只读页）；
  - **ExactlyOne 组**在清单里其选项名对不上（大小写/HTML 转义/前缀）；
  - `NotUsable` 介绍页与 `Required` 插件叠加导致的计数（`fomod.cpp:401-415` 已有部分处理）。
- 修复方向（待样例确认）：更鲁棒的归一化匹配（大小写不敏感 + HTML unescape + 忽略非可用项）；对 `ExactlyOne` 若清单解析出 0 个命中，可考虑回退「归档默认选择」并记 warning，而不是直接 pending。

**验收**：重跑 `collection install` 后 `pending` 从 34 降到 **0**（或仅剩确实无选择可推的项，且有明确 note）。

**顺手（可选）**：`collection inspect` 目前把「有 choices」当作可装，**预测不了「choices 能否对上归档」**（本批就因此给了乐观信号）。可在 inspect 里对 FOMOD 做一次轻量校验，或至少把「已解析到 N 个 FOMOD 选择，其中 M 个无法确认匹配」暴露出来。

## P1 — 影响「一键启动」的准确引导

### A11. `next`/`doctor` 不知道合集要求的游戏版本，给出矛盾的步骤

- **现象**：合集目标 `1.6.1170.0`、本机游戏 `1.7.104.0`。`collection install` 的 preflight 会警告版本不匹配；但 `next` 只给：
  - `skse.version`（blocking）「SKSE64 does not match the game: skse64_1_7_104.dll not found」→ `skse install`
  - `farm` → `apply`
- **问题**：`next`/doctor 按**当前游戏版本**算 SKSE，若照做会装 **1.7.104 的 SKSE**，而合集要 1.6.1170 —— **指错路**，且完全没提「先降级游戏」。
- **建议**：读取未完成合集的 `gameVersions`（preflight 已有该数据），当与当前游戏版本不符时插入一条 **`needs_human` 的 blocking 步骤**（如 `downpatch_game`，附 `collection readme` 链接），并把 SKSE 步骤指向**目标版本**。
- **验收**：有未完成且版本不符的合集时，`next` 首步是「降级游戏（needs_human）」，而不是 `skse install`。

### A7. preflight 的 “already here” 只读 `state.json`，不扫 `downloads/`

- **现象**：盘上已有 38GB 下载，preflight 仍显示 `(0 B already here)`、`remaining=全量`。
- **根因**：`cli/cmd_collection.cpp:222-237`，`have` 只看 `st.mods`。
- **建议**：preflight 也做一次按**大小**的快速扫描（不必 md5），或复用 `find_cached` 的轻量版本。
- **验收**：续跑场景下 “already here” 反映已在 `downloads/` 的归档。

## P2 — 小瑕疵

### A8. `human_size` 把 GiB 标成 “GB”
- 位置：`cli/cmd_collection.cpp:205`（及 `cli/output.cpp:24` 的 `human`）。
- 现象：preflight 打 `139.54 GB`，实为 `149.83e9 B = 139.54 GiB`。数字对、单位标签错。
- 建议：改 “GiB” 或按 10^9 显示，二选一并统一。

### A9. 下载进度 `rate`/`eta` 只有少数事件带
- 位置：`cli/events.cpp:274`（仅 `rate > 0` 时附加）、`rate_of`（`:226-233`，窗口不足 1s 返回 0）。
- 现象：`install3.log` 598 条 `op=download` 只有 **77 条**带 `rate`。
- 建议：缓存最近一个非零速率并持续附带；或文档明确「字段可选，消费方需容错」。

### A10. 计数型 op（`downloaded`）的 `rate`/`eta` 语义错
- 位置：`cli/events.cpp:274-277`。
- 现象：`{"op":"downloaded","done":2,"rate":0,...,"eta":32984}`——`rate` 是「个/秒」（极小，截断为 0），`eta` 却用未截断值算；且 `rate` 单位随 op 变化（`download` 是 B/s）。
- 建议：`rate` 截断后为 0 时不要给 `eta`；计数型 op 用 `items_per_sec` 或干脆不给 `rate`；文档标明各 op 的 `rate` 单位。
